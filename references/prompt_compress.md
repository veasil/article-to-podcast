# 单人讲解口播稿 —— 提炼模板（压缩效率驱动）

> 用途：把一篇长文提炼成「单人主播讲解」的口播稿，时长由**压缩效率**决定（高信息密度可多讲），同时大程度忠于原文。

## 一、核心原则

1. **时长弹性，不掐表**：本功能的价值是「信息压缩带来的效率提升」。原文信息密度高、有大量可压缩空间，就值得多讲一会儿（6-12 分钟）；原文本身短/稀疏，就短讲（2-4 分钟）。**先按信息完整性提炼，再量时长，时长匹配密度即可**。
2. **单人**：通篇只有一位主播在讲，不出现「两位主持人对话」。
3. **忠于原文**：只讲原文里有的内容，**不编造、不曲解、不补充个人观点、不评价、不呼吁**。
4. **用户反馈是输入**：如果用户明确要求时长（"5 分钟内"、"讲详细点"），以用户要求为准。历史反馈见 `<skill>/feedback.md`。

## 二、压缩效率评估（提炼前先打分，写入口播稿头部注释，不朗读）

```
原文长度: X 字
口播稿长度: Y 字
压缩率: Y/X
信息密度: 高/中/低
保留度: 核心论点列表（2-4 个）
时长决策: 预计 X 分钟
依据: <一句话说清为什么这个时长合适>
```

## 三、提炼策略（怎么决定讲多长）

- **信息密度高（干货密集、每段都有论点）**：压缩率可以偏高（如 30-40%），但要保留每个核心论点与关键论据，宁可 6-12 分钟讲透。
- **信息密度中**：常规压缩，4-6 分钟。
- **信息密度低 / 原文本身短**：不用为了凑时长注水，2-4 分钟讲完即可。
- 删掉：铺垫寒暄、重复论述、次要例子、冗长引文、脚注式细节、人名罗列。
- 保留：核心论点、关键论据、最重要的 1–2 个例子、结论。
- 顺序：**按原文的论证顺序**走，不要重排结构。
- 语言：尽量**复用原文的关键句/原话**，只做口语化衔接，不大规模改写。

## 四、口播稿结构

```
[开场 · 1-2 句]
「今天给大家讲的是 <作者> 的《<标题>》，核心讲的是：<一句话点出主题>。」

[主体 · 按原文顺序讲清要点]
用口语把每个要点讲清楚，要点之间自然过渡。要点数量由信息密度决定：
密度高可以讲 5-8 个要点，密度低 2-3 个即可。

[收尾 · 1 句]
「以上就是这篇文章的核心内容，我们下期再见。」
```

## 五、口吻示例

- ✅ 「作者的核心观点是，跨学科合作的规模不能一味扩大，因为人多了协调成本会暴涨。」
- ❌ 「这让我想起了……」（不要加入原文没有的联想）
- ❌ 「建议大家都去读读原文」（不要呼吁）

## 六、输出格式

直接输出口播稿**纯文本**（不要 markdown 标题、不要编号、不要括号注释），这段文本会直接交给 TTS 朗读。压缩效率评估写在文件最顶部并用 `<!-- -->` 注释包裹（TTS 前由 LLM 移除）。
